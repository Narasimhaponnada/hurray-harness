hurray-harness

Track every build. Lose fewer hairs.

A live view of AI agents building your product: which lane is on which ticket, what each agent is doing right now, which skill it runs, where every worktree stands on its way to a merge, and what is waiting on you.

Get started View on GitHub

Why

Parallel agents are fast. Keeping track of them is not.

When several AI agents build at once, each in its own git worktree, you lose the thread. hurray-harness answers the questions you keep asking, in one live view, without changing how your harness works.

Which lane is stuck?Failed checks and recode attempts show on the ticket, in red.
What is each agent doing?Its step, skill, model, time on the step and current action.
Who is burning budget?A budget meter per running agent, amber at 80%.
Which branch is drifting?Commits ahead and behind, uncommitted changes, conflicts.
What is waiting on me?Decisions stay pinned on top, with a notification.

One view, three places

In your browser, any terminal, or right inside Claude Code

All three read the same local hub, so they always agree. Use the one that fits how you work.

Two views

Now and Flow, taking turns

Decisions stay pinned on top. Below them, the two views switch every 2 minutes by default, or at your own interval, so nothing is ever more than one turn away. Press a key or a button to pin one.

Now: what is happening, and who is doing it

  • Phase strip from Discovery to Launch, with the skill running each phase.
  • Skills running, and which agents run them.
  • Ticket grid: each step's status and agent. done working failed needs you
  • Under each running ticket: skill, model, time on the step, budget, and what the agent is doing now.
  • Idle agents, on one line.

Flow: how the work moves, and where each lane stands on merging

  • Swimlanes: one row per lane over time, each step a bar colored by the agent's role.
  • PR state at the end of each lane: merging, behind, conflict, or no PR yet.
  • Under each lane, its local worktree: branch, ahead and behind the base, clean or uncommitted, the last commit, and its way into the base.

On your phone

Decide from your phone

When the harness waits on hh ask --wait, your phone tells you. With the Claude app, a Claude Code session sends a push notification and asks you there, with no webhook or tunnel. With Microsoft Teams, a card arrives with one button per option. Either way, the first answer wins and the harness carries on with your choice.

choice=$(hh ask "Pick the database" --option Postgres --option SQLite --wait)

Works with any harness

Connect at your own pace

Each level adds detail. Nothing here changes how your agents or harness run, and every call gives up after a second if the hub is not there.

1

Nothing

Start the hub in your repo. You already get the GitHub milestone, board, epics and issues, every worktree and its path to a merge, and decisions from labels and approval PRs.

2

Tool hooks

Copy the ready-made hook file for Claude Code or Cursor. Edits, commands and subagents appear live, each tied to its ticket through the worktree it happened in.

3

Harness events

Put hh step in front of the commands your harness runs, or post events. You get the full lane grid: steps, agents, models, skills, recodes, budgets and decisions.

# Report a step from any script; output and exit code pass through unchanged
hh step --ticket 42 --lane L1 --step check --agent developer --skill feature-build -- npm test

# Or send an event directly
hh emit '{"kind":"decision.open","decision":{"id":"r1-db","title":"Pick the database"}}'

Get started

Running in a minute

You need Node 22.13 or newer, git, and the GitHub CLI signed in. Try the demo first: it plays out a made-up milestone, with no repo or agents needed. Until the package is on npm, install the .tgz from the latest release the same way.

Try the demo

npm install -g hurray-harness
hh start --demo         # http://127.0.0.1:7311
hh watch                # second terminal

Use it on your repo

cd ~/code/my-product
hh check                # can git, gh and the tracker be read?
hh start                # hub and dashboard
hh watch                # the terminal view

How it works

One small hub on your machine

Your agent tools, your harness, git and GitHub feed one local hub. It keeps an append-only event log, works out live state, and streams it to every view.

Read-onlyIt reads git and GitHub through your own gh sign-in, and never writes, merges or deletes.
Status, not contentIt keeps the action, file path or command, never prompts, file contents or tool output.
Local onlyIt listens on 127.0.0.1 and refuses writes from other websites.
Ready for teamsEvery event carries who, where and which run, so a shared view can merge everyone's log later.
